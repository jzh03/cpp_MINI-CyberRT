**最有价值的已有工作**

- Discovery 驱动 INTRA/SHM/RTPS 自动选路，按 peer 管理后端启停，支持多路径同时活跃。
- Loan/View 用 RAII Lease 保持映射和块生命周期；generation 区分槽位复用，epoch 拒绝旧发送会话的 Loan。
  纯 SHM 可直接提交原块，混合拓扑有 heap 快照和复制退化，而非对所有路径笼统声称零拷贝。
- 修正跨进程共享对象的 vptr/ABI 布局问题，并校验长度、版本、容量；这是比接口封装更有深度的系统问题。
- QoS 不只设置属性，还通过低层 RTPS History 落实历史容量与淘汰策略；Discovery 历史和业务历史分开。
- 正式回归区分构建、运行、超时、环境失败和复验；benchmark 检查接收内容、CPU、有效吞吐和缺失率。

**需要保持诚实的设计与验证边界**

- SHM 允许覆盖、通知丢弃，无可靠重传；`Publish(true)` 不代表业务已经处理。
- 仅支持一个发布线程与后端启停并发；全局 Shutdown 仍有调用顺序要求。
- 纯 SHM Loan 省去中间 Payload 序列化与复制，不等于网络、GPU 或设备端到端零拷贝。
- Discovery 保留历史有 1000 条默认上限，容量耗尽后无全量状态重建；离线业务消息不补发。
- 当前只有 [x86-64 上下文切换汇编](../croutine/swap_x86_64.S)，头文件中的 aarch64 条件分支不足以证明 ARM64 支持。
- Component/DAG、choreography 和统一宿主生命周期仍未完整接通；CPU 亲和及优先级配置也不等于硬实时保证。

这些边界多数已在 README 和架构文档中主动说明，是工程表达的优点。

项目名：MINI CyberRT——基于 cmw 二次开发的 C++ 通信中间件。
下列内容仅应在能够解释实现、复现测试并确认属于本人实际参与范围时采用；选三至四条即可。

- 统一业务与 Discovery QoS 配置，基于 Fast DDS 低层 RTPS History 实现有界历史策略，补充晚加入发现、历史容量、生命周期和异常输入回归。
- 建立独立进程 SHM 性能实验与 30 个正式回归程序；VMware Linux、4 MiB 消息、收发分别绑核条件下，三轮有效吞吐中位数由 1586.4 提升至 2804 MiB/s，约提升 77%。

实验为显式 POSIX SHM、`-O2 -DNDEBUG`、32 槽×8 MiB、1 秒预热、5 秒测量、1 秒排空，
包含数据生成和接收全量校验。三轮 4 MiB Loan 排空后缺失率均为 0%，但普通路径有一轮缺失；
小消息过载时两条路径均有丢弃，不能将该数字表述成普遍无损吞吐或延迟保证。
